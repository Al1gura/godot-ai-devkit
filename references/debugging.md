# 排错经验

## 先取得坏状态

没有真实报错、日志、截图、错误状态或稳定复现步骤时，不先改代码，也不堆诊断输出。先回答“哪里坏了、何时坏、实际状态是什么”。

推荐顺序：

1. 确认用户看到的错误和最短复现；
2. 确认磁盘上的当前代码、场景和资源；
3. 确认编辑器打开的是同一项目和同一版本；
4. 确认运行的是最新实例，日志和场景树不是上次残留；
5. 再判断原因属于代码、数据、缓存、工具通道、渲染或用户工作流。

## 常见假通过

| 表面现象 | 实际风险 | 应对 |
|---|---|---|
| 没有红色解析错误 | 函数可能在中途因非法属性或运行错误停止 | 检查目标版本接口，并验证函数末端产生的状态 |
| 编辑器报错行号与磁盘不一致 | 编辑器缓存或导入状态可能陈旧 | 对比磁盘、当前导入和真实运行，不先重写代码 |
| 运行工具文件存在 | 不代表连接的是当前项目或当前运行实例 | 检查项目路径、实例身份和新鲜日志标记 |
| 无窗口测试一直等画面帧 | 无窗口环境可能不会产生真实渲染事件 | 将纯逻辑与可见窗口渲染测试分开 |
| 直接调用输入函数测试通过 | 绕过了真实界面与未处理输入分发 | 通过视口发送真实坐标事件 |
| 只证明地图没缩放 | 面板可能也没收到滚动，形成假通过 | 同时断言预期动作发生和副作用没有发生 |
| 自动测试全绿 | 入口、文案和工作流仍可能让用户迷路 | 在稳定端到端成果进行产品验收 |
| 重启解决一次问题 | 可能掩盖了根因且不可重复 | 只把重启用于已确认的进程/端口僵死，不当普通修复 |

## 数据安全

- 测试使用临时目录、隔离用户目录或内存数据。
- 不把正式存档、素材库和导入目录当测试夹具。
- 不用清缓存、重载插件或删除导入数据作为第一反应。
- 只停止当前任务启动的进程和窗口。

## 诚实报告

失败、超时、工具不可用、状态陈旧和缺少证据都保留原意。没有结果不是通过，也不是失败；应写成“尚未验证”并说明影响范围。
