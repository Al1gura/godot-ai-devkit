# Godot 2D Foundations

## 项目选择

- 确认像素美术还是连续缩放美术、目标分辨率、宽高比、拉伸策略和输入设备。
- 像素美术明确纹理过滤、整数缩放、相机移动和像素对齐；不要把连续移动与像素对齐规则混在一起。
- 区分 Node2D（二维世界）与 Control（界面）坐标和布局，不用世界节点承担普通界面排版。

## 场景和层级

- 为玩家、敌人、交互物和特效建立清楚的可复用单位；视觉子节点跟随拥有者，规则状态不藏在任意 Sprite（精灵）里。
- 使用 CanvasLayer（画布层）分离世界、HUD（抬头显示）和覆盖效果；确认不同层的输入和相机关系。
- 目标版本支持时使用当前 TileMapLayer（瓦片地图层）方式；项目版本不同必须查询匹配文档，不照搬其他版本示例。
- 大地图按实际加载、编辑和性能需求分块，不为未来无限世界提前建设复杂流送系统。

## 运动和物理

- 在物理帧更新需要稳定碰撞的移动，区分视觉插值和物理真值。
- 碰撞层/遮罩用项目约定的语义规划，避免靠数字散落在代码中。
- Area2D（二维区域）、CharacterBody2D（二维角色体）和 RigidBody2D（二维刚体）按需要的所有权与物理行为选择，不用脚本强行模拟已有物理能力。
- 射线、重叠和导航结果在对象删除、场景切换和异步等待后重新验证。

## 相机和画面

- 相机跟随、边界、缩放、震动和过渡分开控制；震动不永久修改基础位置。
- 视差、灯光、阴影、粒子和自定义绘制先用目标设备验证成本，再扩大数量。
- 使用纹理图集、合适导入和批处理减少状态切换，但优化前先用分析器和可见帧数据确认瓶颈。
- UI 缩放不应跟随世界相机缩放；世界上的交互标签与屏幕界面明确归属。

## 验证

- 自动测试运动、碰撞合同、坐标转换、生成规则和状态变化；
- 运行态检查场景树、信号、相机和对象生命周期；
- 原生可见窗口检查像素抖动、缩放、纹理过滤、灯光、粒子、真实输入和不同分辨率；
- 手感、可读性和视觉层级需要真实玩家/用户产品验收，不能只看数值测试。
