# Godot Project Start

## 先区分新项目和已有项目

- 已有项目：先读取项目指令、`project.godot`、主场景、现有目录、自动加载、插件、测试和 Git 状态；不要重新脚手架化或移动目录。
- 新项目：先确认目标玩家、核心循环、2D/3D、目标平台、主要输入、Godot 精确版本和明确不做的内容，再创建文件。
- 原型：只建立验证核心体验需要的内容，不预建完整生产目录。

## 建立第一个真实成功案例

先实现一条可以从启动走到可见结果的最短链：

1. 项目能够打开并运行；
2. 玩家能够完成一个核心动作；
3. 游戏给出清楚反馈；
4. 退出或重新开始不会破坏数据；
5. 至少一个自动检查能证明最关键的确定性结果。

不要在第一条成功案例前建设通用背包、事件总线、万能状态机、完整设置页或未来内容编辑器。

## 最小目录

只创建实际需要的目录。长期项目通常从下面选择，而不是全部照抄：

```text
assets/       原始和导入资产
scenes/       可实例化场景
scripts/      跨场景或不适合贴近场景的脚本
resources/    自定义 Resource（资源）数据
tests/        自动测试与夹具
docs/         产品、架构和状态记录
addons/       已审核的第三方或自有插件
```

功能较独立时可以按功能垂直组织，让场景、脚本和资源放在一起。服从项目已有方式，不为目录美观迁移无关文件。

## 项目设置

- 确认主场景、渲染器、窗口尺寸、拉伸策略、物理后端、输入动作和目标平台。
- 只添加当前功能需要的 Input Map（输入映射），使用语义动作名，不把硬件按键散落在业务代码中。
- 只有真正跨场景、全生命周期且唯一的服务才加入 Autoload（自动加载）。
- 检查插件的 Godot 版本、许可证、维护状态和导出平台；不因方便而默认启用全部插件。
- 将 `.godot/`、导出产物、临时测试数据和本机路径排除出版本控制；保留 `.import` 之外项目真正需要的源资源和配置。

## 项目真值

在根 `AGENTS.md` 填写产品定位、目标平台、Godot 版本、语言、测试入口、日志入口和不做范围。代码、场景、`project.godot` 与文档矛盾时，公开指出并确认真实状态。

项目使用 Godot 4.7 时，从 `godot-ai-devkit/references/godot-4.7-docs/` 查询不确定接口；其他版本使用匹配版本资料。

## 启动验收

- 从干净克隆或副本打开项目，确认没有依赖未提交的本机文件。
- 运行第一个成功案例和最小自动检查。
- 确认测试不会读取或覆盖正式用户数据。
- 只有核心路径真实可用后，才规划下一批系统。
