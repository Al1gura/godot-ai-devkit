# Godot GDScript

## 先读项目，不先生成代码

1. 确认 Godot 精确版本、现有语言与类型规则、相关场景树、调用方、测试和数据所有者。
2. 搜索项目内已经验证的相似实现。
3. 项目使用 4.7 时，在 `godot-ai-devkit/references/godot-4.7-docs/` 搜索不确定的类名和成员名；其他版本使用匹配资料。
4. 不凭记忆混用 Godot 3 与 Godot 4 的方法、属性、注解和信号写法。

## 类型策略

- 项目已有严格规则时完整服从，包括是否允许 `:=`。
- 新增长期代码默认写清函数参数、返回值、公共边界、重要状态和集合元素类型。
- 不为类型统一批量迁移与当前目标无关的旧代码。
- 空数组、空字典和跨分支返回值显式声明需要的类型，避免运行时赋值检查才失败。
- 不用 `Variant` 或动态字典掩盖已经稳定的数据合同；真正开放的数据边界要验证键、类型和缺省值。

## 命名和结构

- 文件、函数和变量使用 `snake_case`。
- 类和节点使用 `PascalCase`。
- 常量和枚举成员使用 `UPPER_SNAKE_CASE`。
- 私有成员使用 `_` 前缀。
- 信号名称描述已经发生的事件，例如 `health_changed`、`item_equipped`。
- 一个函数承担一个清晰目的；注释解释原因、约束和陷阱，不逐句翻译代码。
- 遵循项目现有脚本成员顺序；新项目保持注解/类、信号、枚举、常量、导出变量、成员、生命周期回调、公共方法、私有方法的稳定顺序。

## 调用和信号

- 对象拥有并明确知道的子对象，优先直接调用。
- 跨所有权边界或一个事件有多个独立监听者时使用信号。
- 不为“解耦”把所有调用都改成全局事件，也不让任意节点通过脆弱的父级路径寻找兄弟节点。
- 连接信号前确认连接生命周期；重复进入场景或重建界面时避免重复连接和悬空回调。

## 生命周期和异步

- 区分 `_init()`、进入场景树、`_ready()`、每帧、物理帧和退出树时对象可用状态。
- `await` 之后重新确认对象仍有效、场景未切换、请求仍是最新一代；不要假设等待期间世界不变。
- 修改场景树、Tree（树形控件）或编辑器对象时，确认当前回调是否允许同步修改；必要时合并意图并延迟执行。
- 长任务、文件读取和线程完成后只在主线程安全地修改场景树。

## 数据和性能

- Resource（资源）保存可编辑/复用数据，Node（节点）承担场景生命周期；按实际用途选择。
- 缓存经过分析确认昂贵且重复的查询，不凭感觉增加全局缓存。
- 不在每帧回调中重复加载资源、创建大量临时对象或无条件遍历整个场景树。
- 优化前先用分析器确认瓶颈；可读和正确优先于微小猜测优化。

## 完成前检查

- 解析和类型检查通过；
- 使用的 API 与项目精确版本一致；
- 新接口有调用方和失败路径；
- 相关自动测试覆盖正常、边界和错误状态；
- 没有改变无关文件、正式用户数据或项目风格。
