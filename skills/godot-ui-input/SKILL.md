# Godot UI and Input

## 先设计用户路径

1. 写清用户此刻要完成的决定或动作。
2. 列出从现有入口到结果的最短步骤。
3. 删除不影响目标完成的字段、按钮、确认和独立页面。
4. 先复用现有入口和上下文，再考虑新增面板。

内部有多个控制器、数据表或命令，不代表用户需要看见同样多的界面。危险且不可恢复的动作才需要额外确认；普通可逆选择应直接、清楚并提供即时反馈。

## 布局

- 使用 Container（容器）、锚点、尺寸标志和 Theme（主题）表达布局，不用大量绝对坐标拼界面。
- 测试目标窗口尺寸、最小尺寸、宽高比、界面缩放和文本增长。
- 信息按用户决策顺序排列，主动作保持明显，低频高级选项折叠或延后。
- 不用颜色作为唯一状态信号；为键盘、手柄和触摸保留可操作路径。
- 投屏、分屏或多窗口分别考虑可见范围、字体大小和隐私，不假设主窗口布局可以直接复制。

## 输入所有权

- 先查目标版本的 InputEvent（输入事件）分发顺序和 Control 行为，不凭印象处理。
- Control 在 `_gui_input()` 中处理并 `accept_event()`（接收事件）；世界、角色或相机等全局交互优先放在 `_unhandled_input()`（未处理输入），让界面先获得事件。
- 为外层界面区域设置明确 `mouse_filter`（鼠标过滤）边界，不让任意内部子控件决定整个面板是否漏事件。
- 覆盖在世界上的滚动区域关闭 `mouse_force_pass_scroll_events`（强制传递滚轮事件）；滚动到顶部或底部也不能把滚轮交给地图或相机。
- 拖放、焦点、快捷键和手柄导航明确取消、失焦、场景切换和目标失效时如何恢复。
- 不用 `_input()` 抢在所有界面之前实现普通世界操作，除非确实需要全局、不可拦截的行为并有明确理由。

## 自动验证

- 通过 Viewport（视口）发送带真实坐标的输入事件，不只直接调用 `_input()` 或 `_gui_input()`。
- 同时断言正向结果和禁止副作用，例如“列表滚动了，并且相机没有缩放”。
- 滚动覆盖正常位置、顶部、底部、界面边缘和世界空白区。
- 拖放覆盖有效目标、无效目标、取消、目标删除和离开窗口。
- 焦点和快捷键覆盖文本输入、弹窗、菜单、游戏世界和场景切换。

## 原生可见窗口

真实鼠标/键盘分发、窗口焦点、多显示器、分辨率缩放、拖出窗口、系统文件拖入和图形渲染必须在原生可见窗口验证。自动逻辑通过不能代替这一层。

高频、多步骤、关键文案、难以恢复或主观可读性改变时，在稳定端到端成果上安排用户产品验收；不要把临时脚手架交给用户反复测试。
